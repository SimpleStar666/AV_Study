- 关键修复链（含最终断流根因，每步都是独立教学点）：
  1. **mediaServerId 修复**：ZLM hook `推流鉴权` 响应「找不到对应的mediaServer」→ wvp yml media 段 `id: your_server_id`（与 ZLM config.ini secret 段配套）；sed 曾误伤 sip 段 id，需手动还原
  2. **-f vob 缺 Program Stream Map**（ffprobe 认不出编码）→ 改 `-f mpeg`（标准 MPEG-2 PS）
  3. **ffmpeg 无法输出 H.264-in-PS**（vob/mpeg muxer 不支持 H.264）→ **自研 PS 打包器**：`ffmpeg -f h264` 裸流 + Python 组 pack/system/PSM/PES
  4. **PES 头 flags1 必须是 0x80**（`'10'` 标记在最前 2 位；误写 0x10 → ffprobe Invalid data）
  5. **pack 头第一字节决定解析模式**：`0x21` → MPEG-1 模式（PES 按 MPEG-1 解析，MPEG-2 风格的 `80 80 05` PES 头错位失败）；`0x44` → MPEG-2 模式 → PES 头正确解析。**pack 头 = PES 解析模式开关**
  6. **PSM 结构**：`00 00 01 BC` + map_length=0x0E + current_next/reserved=0x01 + psm_info_len=0 + esm_len=4 + `stream_type=0x1B(H264) ES=0xE0` + CRC 占位。**libmpeg 无 PSM 时 psm_fetch 返回 NULL → PES 被跳过 → 不建流**（ZLM 源码 mpeg-ps-dec.c 实证）
  7. **单 slice 编码**：libx264 多线程把每帧切 3 slice → 分帧逻辑把 slice 当帧 → PTS 乱序（ffmpeg 报 `DTS out of order`）→ ZLM 不建流。加 `-threads 1 -x264-params slices=1` → 帧边界正确
  8. **RTP marker 位**：marker 必须在 RTP 头 byte1 bit7（`0x80|m`）；误作字节 0 → ffmpeg `mb_type 384` 解码崩
  9. **PTS/RTP ts 同源**：RTP timestamp 必须 = PES PTS（同一 90000Hz 时钟）；不同源 → 帧序乱
  10. **ffmpeg -re 在 WSL 失效（全速 65fps 输出）**：`timeout 5 ... | wc -c` 实测 195KB（应为 45KB）→ 模拟器超高速推流 → ZLM EPOLLET edge 触发竞态断流（收 ~1.5-3s 停）。**根治：模拟器自限速 `time.sleep(0.066)` 每帧**（FRAME_INTERVAL=15fps），不依赖 -re
  11. **流式 AnnexB 切分**：旧版"找 start code 后丢弃整块"会丢跨 chunk 的 NAL 数据（帧截断 → 每帧 concealing 花屏）；改为保留残留 buf 的流式切分
  12. **PS payload 必须保留 start code**：新版切分曾剥离 `00 00 00 01`，ZLM GB28181Process 依赖 sc 切 NAL → 首包后 15s 无 track（收流超时）；**切分保留 sc + nal_type 按含 sc 读偏移** → 点播 1 秒返回成功

  4. **usbipd 挂载**：Windows 侧 `usbipd bind --busid=1-11`（Shared）→ WSL 内 `sudo modprobe vhci_hcd && sudo usbip attach -r 127.0.0.1 -b 1-11`（镜像网络用 127.0.0.1）；`usbipd attach --wsl` 在本环境不生效
